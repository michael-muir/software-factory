# Shell standards pack

Rules a reviewer judges in shell scripts. Each rule is in our own words and links the section of the source it comes from. Cite a rule by its id in a finding. Severity follows ADR 0037: `blocker` for unsafe or incorrect code, `major` for code that misleads or is hard to change, `minor` for readability.

## Left to the tools

The gate's format check (`shfmt`) and lint check (`shellcheck`) will own layout, quoting, `$(...)` over backticks and the other mechanical rules, once a shell profile lands. Run them by hand until then. This pack doesn't repeat them.

## Rules

| Rule id | Severity | Rule                                                                                                                                  | Why/example                                                              | Source                                                                                                                                                 |
| ------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| SH-001  | blocker  | Check the result of every command that can fail, with `if`, `\|\|` or a deliberate `set -e` strategy.                                 | A failed `cd` followed by `rm -rf *` deletes the wrong folder.           | [Google Shell: Checking Return Values](https://google.github.io/styleguide/shellguide.html#s8.1-checking-return-values)                                |
| SH-002  | blocker  | Never use `eval`.                                                                                                                     | It runs data as code, and makes the script impossible to reason about.   | [Google Shell: eval](https://google.github.io/styleguide/shellguide.html#s6.6-eval)                                                                    |
| SH-003  | blocker  | Never make a script SUID or SGID. Use `sudo` where privilege is needed.                                                               | A privileged script is an easy way to take over the machine.             | [Google Shell: SUID/SGID](https://google.github.io/styleguide/shellguide.html#s2.2-suid-sgid)                                                          |
| SH-004  | blocker  | Don't pipe into a `while` loop that sets variables you need afterwards. Use process substitution or `readarray`.                      | The loop runs in a subshell, so its variables are gone when it ends.     | [Google Shell: Pipes to While](https://google.github.io/styleguide/shellguide.html#s6.8-pipes-to-while)                                                |
| SH-005  | major    | Pass lists of arguments in arrays, not in space-separated strings.                                                                    | A file name with a space becomes two arguments.                          | [Google Shell: Arrays](https://google.github.io/styleguide/shellguide.html#s6.7-arrays)                                                                |
| SH-006  | major    | Use an explicit path with wildcards: `./*`, not `*`.                                                                                  | A file named `-rf` is read as an option.                                 | [Google Shell: Wildcard Expansion of Filenames](https://google.github.io/styleguide/shellguide.html#s6.5-wildcard-expansion-of-filenames)              |
| SH-007  | major    | Write executables in bash, starting with `#!/bin/bash`, with as few flags as possible.                                                | One shell means one set of rules for every script.                       | [Google Shell: Which Shell to Use](https://google.github.io/styleguide/shellguide.html#s1.1-which-shell-to-use)                                        |
| SH-008  | major    | Move to a real language once a script grows past about 100 lines, or needs complex control flow or data structures.                   | Shell gets fragile quickly as it grows.                                  | [Google Shell: When to use Shell](https://google.github.io/styleguide/shellguide.html#s1.2-when-to-use-shell)                                          |
| SH-009  | major    | Send error messages to stderr.                                                                                                        | Callers that capture stdout then get only the output.                    | [Google Shell: STDOUT vs STDERR](https://google.github.io/styleguide/shellguide.html#s3.1-stdout-vs-stderr)                                            |
| SH-010  | major    | Declare a function's variables with `local`.                                                                                          | Otherwise they leak into the caller's scope.                             | [Google Shell: Use Local Variables](https://google.github.io/styleguide/shellguide.html#s7.6-use-local-variables)                                      |
| SH-011  | minor    | Put the code in functions, with a `main` function called at the end, once a script has more than one function.                        | The entry point is easy to find, and variables stay local.               | [Google Shell: main](https://google.github.io/styleguide/shellguide.html#s7.8-main)                                                                    |
| SH-012  | minor    | Prefer `[[ ... ]]` to `[ ... ]` and `test`.                                                                                           | `[[` doesn't split words or expand globs, and supports pattern matching. | [Google Shell: Tests](https://google.github.io/styleguide/shellguide.html#s6.3-tests)                                                                  |
| SH-013  | minor    | Start every file with a comment saying what it does.                                                                                  | The reader knows what the script is for before reading it.               | [Google Shell: File Header](https://google.github.io/styleguide/shellguide.html#s4.1-file-header)                                                      |
| SH-014  | minor    | Comment every function that isn't both short and obvious: the globals it uses, its arguments, its output and its return value.        | Shell signatures say nothing about any of these.                         | [Google Shell: Function Comments](https://google.github.io/styleguide/shellguide.html#s4.2-function-comments)                                          |
| SH-015  | minor    | Name functions and variables in lower_snake_case. Name constants and exported variables in UPPER_CASE, and make constants `readonly`. | The case tells the reader what may change.                               | [Google Shell: Naming Conventions](https://google.github.io/styleguide/shellguide.html#s7-naming-conventions)                                          |
| SH-016  | minor    | Do arithmetic with `(( ))` or `$(( ))`, never with `let`, `expr` or `$[ ]`.                                                           | One form is easier to read and less error-prone.                         | [Google Shell: Arithmetic](https://google.github.io/styleguide/shellguide.html#s6.9-arithmetic)                                                        |
| SH-017  | minor    | Prefer builtins and parameter expansion to external commands for simple string work.                                                  | `${path##*/}` is faster and more portable than calling `basename`.       | [Google Shell: Builtin Commands vs. External Commands](https://google.github.io/styleguide/shellguide.html#s8.2-builtin-commands-vs-external-commands) |
| SH-018  | minor    | Use functions rather than aliases in scripts.                                                                                         | Aliases are hard to read and behave differently in scripts.              | [Google Shell: Aliases](https://google.github.io/styleguide/shellguide.html#s6.10-aliases)                                                             |
