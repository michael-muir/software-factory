# C++ standards pack

Rules a reviewer judges in C++ code. Each rule is in our own words and links the section of the source it comes from. Cite a rule by its id in a finding. Severity follows ADR 0037: `blocker` for unsafe or incorrect code, `major` for code that misleads or is hard to change, `minor` for readability.

## Left to the tools

The gate's format check (`clang-format`) and lint check (`clang-tidy` or `cpplint`, with the project's config) will own layout, include guards and the mechanical rules once the C++ profile lands (E30). This pack doesn't repeat them. Its links name the guide's section; they point to the guide's page, because its section anchors weren't checked.

## Rules

| Rule id | Severity | Rule                                                                                                                                                            | Why/example                                                                                      | Source                                                                                            |
| ------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| CPP-001 | blocker  | Give every heap object one clear owner: `std::unique_ptr`, or `std::shared_ptr` when ownership really is shared. No `new` without an owner.                     | A raw owning pointer leaks on the first early return.                                            | [Google C++: Ownership and Smart Pointers](https://google.github.io/styleguide/cppguide.html)     |
| CPP-002 | blocker  | Objects with static storage duration are trivially destructible: no global or static `std::string`, `std::map` or similar.                                      | Their destructors run in an unspecified order at exit, and can use objects already destroyed.    | [Google C++: Static and Global Variables](https://google.github.io/styleguide/cppguide.html)      |
| CPP-003 | blocker  | Don't call virtual functions in constructors or destructors.                                                                                                    | The call goes to the base class's version, not the override you expected.                        | [Google C++: Doing Work in Constructors](https://google.github.io/styleguide/cppguide.html)       |
| CPP-004 | blocker  | A lambda that can outlive its scope captures explicitly. No `[&]` or `[=]` on callbacks that are stored or deferred.                                            | A default by-reference capture dangles once the scope ends.                                      | [Google C++: Lambda Expressions](https://google.github.io/styleguide/cppguide.html)               |
| CPP-005 | major    | Mark single-argument constructors and conversion operators `explicit`, unless the implicit conversion is the point.                                             | Implicit conversions call code the reader can't see.                                             | [Google C++: Implicit Conversions](https://google.github.io/styleguide/cppguide.html)             |
| CPP-006 | major    | Don't use `using namespace` directives.                                                                                                                         | They pull in names you didn't ask for, and a later library version can break the build.          | [Google C++: Namespaces](https://google.github.io/styleguide/cppguide.html)                       |
| CPP-007 | major    | Don't do work that can fail in a constructor. Use a factory function that can report the failure.                                                               | Without exceptions, a constructor has no way to say it failed.                                   | [Google C++: Doing Work in Constructors](https://google.github.io/styleguide/cppguide.html)       |
| CPP-008 | major    | Mark every overriding function `override` or `final`, and don't repeat `virtual` on it.                                                                         | A signature that drifts from the base then fails to compile, instead of silently not overriding. | [Google C++: Inheritance](https://google.github.io/styleguide/cppguide.html)                      |
| CPP-009 | major    | Make a class's copy and move behaviour explicit: declare the operations, or `= delete` them.                                                                    | The reader sees at once whether copying is safe.                                                 | [Google C++: Copyable and Movable Types](https://google.github.io/styleguide/cppguide.html)       |
| CPP-010 | major    | Use `const` for references, pointers and methods that don't change state.                                                                                       | `const` tells the reader and the compiler what can't change.                                     | [Google C++: Use of const](https://google.github.io/styleguide/cppguide.html)                     |
| CPP-011 | major    | Use C++ casts (`static_cast`, `const_cast`, `reinterpret_cast`), never C-style casts.                                                                           | A C-style cast can do any of them, silently.                                                     | [Google C++: Casting](https://google.github.io/styleguide/cppguide.html)                          |
| CPP-012 | major    | Don't switch on run-time type with chains of `dynamic_cast` or `typeid`. Use virtual functions or a visitor.                                                    | Type switches break each time a new subclass appears.                                            | [Google C++: Run-Time Type Information (RTTI)](https://google.github.io/styleguide/cppguide.html) |
| CPP-013 | major    | Use `int` for ordinary integers and `<cstdint>` types (`int64_t`) when the size matters. Don't use unsigned types just to say a value is never negative.        | Unsigned arithmetic wraps around instead of going negative, and hides bugs.                      | [Google C++: Integer Types](https://google.github.io/styleguide/cppguide.html)                    |
| CPP-014 | minor    | Use `nullptr` for null pointers, never `NULL` or `0`.                                                                                                           | `nullptr` can't be mistaken for an integer in overloads.                                         | [Google C++: 0 and nullptr/NULL](https://google.github.io/styleguide/cppguide.html)               |
| CPP-015 | minor    | Follow the guide's naming: types in UpperCamelCase, variables in snake_case, class data members with a trailing underscore, constants as `kName`.               | The name tells the reader what kind of thing it is.                                              | [Google C++: Naming](https://google.github.io/styleguide/cppguide.html)                           |
| CPP-016 | minor    | A function's comment says what it does and what the caller must know: ownership of pointer arguments, whether they may be null, and what it returns on failure. | Those facts aren't in the signature.                                                             | [Google C++: Function Comments](https://google.github.io/styleguide/cppguide.html)                |
| CPP-017 | minor    | Keep functions short and focused. Split one that grows past about 40 lines when that helps the reader.                                                          | Short functions are easier to test and to change.                                                | [Google C++: Write Short Functions](https://google.github.io/styleguide/cppguide.html)            |
| CPP-018 | minor    | Use `auto` where it makes code clearer, not to hide a type the reader needs.                                                                                    | `auto it = map.find(key)` helps; `auto x = Compute()` hides what `x` is.                         | [Google C++: Type Deduction](https://google.github.io/styleguide/cppguide.html)                   |
