## Goal

The resumed live run on #82 (job `e31-evidence-tags`, runner job `t1-3`, 27 Nov 2026; issue #115) found two things. All six reviews passed, then `check review` stopped the job because the Adversary's new attack test, `tests/test_attack_evidence_tags.py`, came after the gated commit. And all five reviewers without a shell got `handoff = missing`, because their replies didn't use the exact headings the driver looks for. The product owner's decisions of 27 Nov 2026 (#115): at the end of review, files added under `tests/` since the gated commit pass too, since the docs stage gates the new head again before the PR; and the prompt for a role without a shell names the three headings, in order.

## Acceptance criteria

- E13 AC-13 (amended 27 Nov 2026): `check review` accepts a gate report for a commit whose later changes are under `.agentic/`, or are files added under `tests/`. A modified or deleted file outside `.agentic/`, or any other new file, still needs a fresh gate. The check before each pending reviewer keeps the stricter rule: only `.agentic/`.
- E13 AC-07 (amended 27 Nov 2026): the prompt for a role without a shell names the handoff note's headings exactly, in order: `## Done`, `## Next`, `## Open questions`. Its last line stays the no-commit line, and the Verifier's verdict line still ends its reply, after the handoff note.

## Notes

- `_gate_for_review(c, allow_added_tests=True)` is used only by `_check_review`. Renames count as a delete and an add (`--no-renames`), so renaming an existing file still needs a fresh gate.
- The headings go in a line of their own just before the no-commit line, so E13-T7's locked tests, which pin that last line, stay as they are.
