## Goal

Follow-up to PR #68, agreed by the product owner on 20 Nov 2026. A role's `run` scope is a list of command prefixes, and the shell control check stops chaining. But a command allowed by its prefix can still write a file through its own options. For example, the verifier's `git diff` and `git log` prefixes allow `git log --output=notes.txt`, which writes `notes.txt` in any shell. A read-only role like the verifier shouldn't be able to write that way.

## Acceptance criteria

- For a role whose tools don't include `edit` or `write`, `run` commands with git's `--output` or `--output=<file>` option are denied, with a reason that names the option.
- The rule's list of file-writing options is a table in `agents.py`, documented in `_schema.md`, so other commands can be added.
- A role that may write (`edit` or `write` in its tools) keeps today's behaviour.
- Tests cover the git forms (`--output <file>`, `--output=<file>`, `-o` where git accepts it), in a POSIX and a PowerShell payload.
