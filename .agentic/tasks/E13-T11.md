## Goal

Two gaps from the live run on #82 (runner job `e31-evidence-tags-t1-5`, 28 Nov 2026; issue #120, which also covers #119). On the product owner's Windows machine, mutation passed with no mutant scored, because its kill test failed before any mutation and `mutate_python.py` exited 0. And after the Verifier rightly failed the slice, `resume` couldn't get the code gated again, because the only later change was under `.agentic/`; a red gate in review had the same gap.

## Acceptance criteria

- E06 AC-10 (amended 28 Nov 2026): when the kill test fails in the copy and in the project, `mutate_python.py` exits 1, a mutation failure, and says that the kill test fails before any mutation, so no mutant can be scored.
- E06 AC-10: it prints the tail of pytest's output, its last 30 lines with the short test summary, so the failing test is named.
- E06 AC-10: a kill test that passes in the project but fails in the copy is still an environment error (exit 2).
- E06 AC-10: the seeded failing-test variant fails the tests and mutation checks.
- E13 AC-13 (amended 28 Nov 2026): on a new attempt at review, before any reviewer or gate in it, the driver runs the full gate again when the previous attempt at review ended red (a red gate in review, or a Verifier that failed, gave no verdict or didn't finish), even when the head differs from the newest gate only under `.agentic/`, and even when the newest report is red.
- E13 AC-13: when that gate is green, the Verifier and the reviewers run against it; when it's red, the job stops as `needs-human`.
- E13 AC-13: a resume after a previous attempt that didn't end red keeps the rule for #117, so it doesn't gate again needlessly.
- E13 AC-13: at most one gate again per attempt.
