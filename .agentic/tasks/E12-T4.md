## Goal

First a follow-up to PR #68, agreed by the product owner on 20 Nov 2026. After the AC-11 live check failed on Windows the same day, the product owner moved it into PR #68. Claude Code on Windows has a `PowerShell` tool, and its hooks docs use the matcher `Bash|PowerShell`. The factory's `.claude/settings.json` matcher and `CLAUDE_CODE_TOOLS` list only the spec's tools. So where the PowerShell tool is turned on, its calls skip the hook: a role can run any command, and locks don't apply. This slice maps `PowerShell` to the neutral `run` and adds it to the matcher.

## Acceptance criteria

- E12's tool table (spec) lists Claude Code's `PowerShell` tool under `run`. This is a spec change, for the product owner to approve.
- `CLAUDE_CODE_TOOLS` maps `PowerShell` to `run`, and the generated `PreToolUse` matcher includes it.
- A PowerShell call outside a role's `run` scope is denied, and an in-scope one is allowed. Its input is read from `tool_input.command`, as for Bash.
- PowerShell syntax that runs or chains a command (`(...)`, `@(...)`, `$var`, `$x.Method()`, `&&`, `||`, and line or paragraph separators) counts as shell control, as `;`, `|`, `&`, backtick, `$(` and `>` already do.
- The tests that pin the tool table and the Claude Code entry (E03 and E12-T2) are updated, through a relock the product owner approves.

## Notes

- Source: code.claude.com/docs/en/hooks (checked 20 Nov 2026). Its matcher example is `Bash|PowerShell`. Its PreToolUse section gives the PowerShell tool's input: "The fields match the Bash tool, with the command string in `command`". A subagent's call carries `agent_id` and `agent_type`, which the hook already reads.
- Tests: `tests/test_adapters_powershell.py`, locked for this task. The pinned tables in E03-T3's and E12-T2's locked tests need a relock, which waits for the product owner's approval.
