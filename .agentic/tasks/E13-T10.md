## Goal

Resuming the live run on #82 at the review stage (runner job `e31-evidence-tags-t1-4`, 28 Nov 2026; issue #117) stopped at once. `resume` starts a new attempt, so every reviewer is pending again, and the previous round's Adversary had committed `tests/test_attack_evidence_tags.py` after the gated commit, so the strict check before the first reviewer failed. Now the driver gates the head again in that case, instead of stopping.

## Acceptance criteria

- E13 AC-13 (amended 28 Nov 2026): when no reviewer has run in the attempt, and the newest gate report is a pass but the head has changes outside `.agentic/` since its commit, the driver runs the full gate again. When that gate is green, the reviews start against it.
- E13 AC-13: when that gate is red, the job stops as `needs-human`, its reason names the failed checks, and no reviewer runs. There's no Debugger loop in review.
- E13 AC-13: when the head differs from the gated commit only under `.agentic/`, the driver doesn't gate again.
- E13 AC-13: the check before each later reviewer stays strict, so a reviewer that changes code still stops the job, with no gate run again.
- E13 AC-13: the driver gates again at most once per attempt, and stops if the head still differs after it.
