# Unreal Engine C++ standards pack

Rules a reviewer judges in Unreal Engine C++ code (UE 5.4 and later). In a repo with a `.uproject` at its root it replaces the Google C++ pack, because the two disagree on naming and language features. Each rule is in our own words and links the section of the source it comes from. Cite a rule by its id in a finding. Severity follows ADR 0037: `blocker` for unsafe or incorrect code, `major` for code that misleads or is hard to change, `minor` for readability.

## Left to the tools

The gate's format check (`clang-format`, with the project's Unreal config) and lint check will own layout, braces and the mechanical rules once the Unreal profile lands (E30). Unreal Header Tool and the compiler catch the rest. This pack doesn't repeat them. Its links name the standard's section; they point to the standard's page, because its section anchors weren't checked.

## Rules

| Rule id | Severity | Rule                                                                                                                                                                                                           | Why/example                                                                               | Source                                                                                                                                                         |
| ------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| UE-001  | blocker  | Use the engine's type prefixes: `U` for UObject classes, `A` for actors, `S` for Slate widgets, `F` for other structs and classes, `E` for enums, `I` for interfaces, `T` for templates, and `b` for booleans. | Unreal Header Tool rejects reflected types with the wrong prefix, and readers rely on it. | [Epic standard: Naming Conventions](https://dev.epicgames.com/documentation/en-us/unreal-engine/epic-cplusplus-coding-standard-for-unreal-engine)              |
| UE-002  | blocker  | A lambda that is stored or deferred (a delegate, a timer, an async task) captures explicitly, never with `[&]` or `[=]`.                                                                                       | A by-reference capture dangles once the scope or the object is gone.                      | [Epic standard: Lambdas and Anonymous Functions](https://dev.epicgames.com/documentation/en-us/unreal-engine/epic-cplusplus-coding-standard-for-unreal-engine) |
| UE-003  | major    | Use the engine's sized types (`int32`, `uint8`, `int64`) where size matters, and in anything serialised or exposed to Blueprints.                                                                              | `int` and `long` change size between platforms.                                           | [Epic standard: Portable C++ code](https://dev.epicgames.com/documentation/en-us/unreal-engine/epic-cplusplus-coding-standard-for-unreal-engine)               |
| UE-004  | major    | Prefer the engine's containers and strings (`TArray`, `TMap`, `FString`) to the standard library's in engine-facing code.                                                                                      | Engine APIs, reflection and serialisation expect them.                                    | [Epic standard: Use of Standard Libraries](https://dev.epicgames.com/documentation/en-us/unreal-engine/epic-cplusplus-coding-standard-for-unreal-engine)       |
| UE-005  | major    | Mark every overriding function `override`, and don't repeat `virtual` on it.                                                                                                                                   | A signature that drifts from the base then fails to compile.                              | [Epic standard: Modern C++ Language Syntax](https://dev.epicgames.com/documentation/en-us/unreal-engine/epic-cplusplus-coding-standard-for-unreal-engine)      |
| UE-006  | major    | Use `enum class` for new enums, with `UENUM()` where they're exposed to reflection.                                                                                                                            | Scoped enums don't leak names, and don't convert silently to integers.                    | [Epic standard: Strongly-Typed Enums](https://dev.epicgames.com/documentation/en-us/unreal-engine/epic-cplusplus-coding-standard-for-unreal-engine)            |
| UE-007  | major    | Include what you use, and forward-declare where a full definition isn't needed.                                                                                                                                | Headers stay light, and build times stay down.                                            | [Epic standard: Physical Dependencies](https://dev.epicgames.com/documentation/en-us/unreal-engine/epic-cplusplus-coding-standard-for-unreal-engine)           |
| UE-008  | major    | Never put `using namespace` at global scope or in a header.                                                                                                                                                    | Unity builds merge files, so the directive leaks into code that never asked for it.       | [Epic standard: Namespaces](https://dev.epicgames.com/documentation/en-us/unreal-engine/epic-cplusplus-coding-standard-for-unreal-engine)                      |
| UE-009  | major    | In APIs, use enums or flag structs instead of `bool` parameters.                                                                                                                                               | `Load(Path, ELoadFlags::Async)` reads; `Load(Path, true)` doesn't.                        | [Epic standard: API Design Guidelines](https://dev.epicgames.com/documentation/en-us/unreal-engine/epic-cplusplus-coding-standard-for-unreal-engine)           |
| UE-010  | major    | Use `const` wherever it's true: arguments, methods, return values and locals.                                                                                                                                  | `const` tells the reader and the compiler what can't change.                              | [Epic standard: Const Correctness](https://dev.epicgames.com/documentation/en-us/unreal-engine/epic-cplusplus-coding-standard-for-unreal-engine)               |
| UE-011  | major    | Keep data members private or protected behind accessors, unless the type is plain data.                                                                                                                        | Callers can't bypass the invariants your methods keep.                                    | [Epic standard: Encapsulation](https://dev.epicgames.com/documentation/en-us/unreal-engine/epic-cplusplus-coding-standard-for-unreal-engine)                   |
| UE-012  | major    | Keep platform-specific code in platform folders or behind `PLATFORM_` macros.                                                                                                                                  | Every other platform's build stays clean.                                                 | [Epic standard: Platform-Specific Code](https://dev.epicgames.com/documentation/en-us/unreal-engine/epic-cplusplus-coding-standard-for-unreal-engine)          |
| UE-013  | minor    | Use `nullptr`, never `NULL` or `0`.                                                                                                                                                                            | `nullptr` can't be mistaken for an integer.                                               | [Epic standard: nullptr](https://dev.epicgames.com/documentation/en-us/unreal-engine/epic-cplusplus-coding-standard-for-unreal-engine)                         |
| UE-014  | minor    | Names describe what they hold or do. Functions that return a `bool` ask a question (`IsVisible`, `ShouldTick`).                                                                                                | The call site reads as a sentence.                                                        | [Epic standard: Naming Conventions](https://dev.epicgames.com/documentation/en-us/unreal-engine/epic-cplusplus-coding-standard-for-unreal-engine)              |
| UE-015  | minor    | Write code that explains itself, and comments that say why.                                                                                                                                                    | The code already says what; the reason is what gets lost.                                 | [Epic standard: Comments](https://dev.epicgames.com/documentation/en-us/unreal-engine/epic-cplusplus-coding-standard-for-unreal-engine)                        |
| UE-016  | minor    | Wrap string literals in `TEXT()`.                                                                                                                                                                              | Literals then use the engine's character type on every platform.                          | [Epic standard: Character Encoding](https://dev.epicgames.com/documentation/en-us/unreal-engine/epic-cplusplus-coding-standard-for-unreal-engine)              |
| UE-017  | minor    | Organise a class with its public interface first and its private implementation after.                                                                                                                         | Readers of the header see what they can use first.                                        | [Epic standard: Class Organization](https://dev.epicgames.com/documentation/en-us/unreal-engine/epic-cplusplus-coding-standard-for-unreal-engine)              |
| UE-018  | minor    | Use `auto` only where the standard allows it, such as iterators and lambdas, not to hide a type the reader needs.                                                                                              | In engine code the type is usually the most useful thing on the line.                     | [Epic standard: auto](https://dev.epicgames.com/documentation/en-us/unreal-engine/epic-cplusplus-coding-standard-for-unreal-engine)                            |
