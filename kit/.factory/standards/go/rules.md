# Go standards pack

Rules a reviewer judges in Go code. Each rule is in our own words and links the section of the source it comes from. Cite a rule by its id in a finding. Severity follows ADR 0037: `blocker` for unsafe or incorrect code, `major` for code that misleads or is hard to change, `minor` for readability.

## Left to the tools

The gate's format check (`gofmt` or `goimports`) and lint check (`go vet`, plus the project's linters) will own layout, imports and the mechanical rules once the Go profile lands (E30). This pack doesn't repeat them.

## Rules

| Rule id | Severity | Rule                                                                                                                    | Why/example                                                                            | Source                                                                                                                                            |
| ------- | -------- | ----------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| GO-001  | blocker  | Use the two-value form of a type assertion (`t, ok := v.(T)`), unless a panic is truly what you want.                   | The one-value form panics on the first unexpected type.                                | [Uber Go: Handle Type Assertion Failures](https://github.com/uber-go/guide/blob/master/style.md#handle-type-assertion-failures)                   |
| GO-002  | blocker  | Don't panic in library or service code. Return an error and let the caller decide.                                      | A panic takes the whole process down for one bad request.                              | [Uber Go: Don't Panic](https://github.com/uber-go/guide/blob/master/style.md#dont-panic)                                                          |
| GO-003  | blocker  | Never start a goroutine without a way to stop it and a way to wait until it has exited.                                 | Leaked goroutines hold memory and connections until the process dies.                  | [Uber Go: Don't fire-and-forget goroutines](https://github.com/uber-go/guide/blob/master/style.md#dont-fire-and-forget-goroutines)                |
| GO-004  | blocker  | Copy slices and maps at API boundaries when you keep one you were given, or return one you keep.                        | Otherwise the caller can change your internal state.                                   | [Uber Go: Copy Slices and Maps at Boundaries](https://github.com/uber-go/guide/blob/master/style.md#copy-slices-and-maps-at-boundaries)           |
| GO-005  | blocker  | Handle each error once: wrap and return it, or log it and carry on. Never both.                                         | Logging and returning prints the same failure at every level.                          | [Uber Go: Handle Errors Once](https://github.com/uber-go/guide/blob/master/style.md#handle-errors-once)                                           |
| GO-006  | major    | Wrap errors with the context the caller lacks, using `%w`: `fmt.Errorf("open config: %w", err)`. Leave out "failed to". | The message chain then reads like a path to the cause.                                 | [Uber Go: Error Wrapping](https://github.com/uber-go/guide/blob/master/style.md#error-wrapping)                                                   |
| GO-007  | major    | Check interface compliance at compile time where it matters: `var _ http.Handler = (*Handler)(nil)`.                    | The build breaks when the type stops satisfying the interface.                         | [Uber Go: Verify Interface Compliance](https://github.com/uber-go/guide/blob/master/style.md#verify-interface-compliance)                         |
| GO-008  | major    | Avoid mutable package-level variables. Pass dependencies in instead.                                                    | Globals make tests share state and order-dependent.                                    | [Uber Go: Avoid Mutable Globals](https://github.com/uber-go/guide/blob/master/style.md#avoid-mutable-globals)                                     |
| GO-009  | major    | Avoid `init()`. If you must have one, it's deterministic, does no I/O, and starts no goroutines.                        | `init()` runs on import, before anything can handle its errors.                        | [Uber Go: Avoid init()](https://github.com/uber-go/guide/blob/master/style.md#avoid-init)                                                         |
| GO-010  | major    | Don't embed types in exported structs.                                                                                  | Embedding leaks the inner type's methods into your API, and you can never remove them. | [Uber Go: Avoid Embedding Types in Public Structs](https://github.com/uber-go/guide/blob/master/style.md#avoid-embedding-types-in-public-structs) |
| GO-011  | major    | Use `time.Time` for instants and `time.Duration` for periods, not plain integers.                                       | `Poll(10)` doesn't say whether that's seconds or milliseconds.                         | [Uber Go: Use time to handle time](https://github.com/uber-go/guide/blob/master/style.md#use-time-to-handle-time)                                 |
| GO-012  | major    | Channels are unbuffered or have a size of one. Any other size needs a stated reason.                                    | A bigger buffer hides back-pressure until it fills in production.                      | [Uber Go: Channel Size is One or None](https://github.com/uber-go/guide/blob/master/style.md#channel-size-is-one-or-none)                         |
| GO-013  | major    | Call `os.Exit` or `log.Fatal` only in `main()`, and only once.                                                          | Exiting elsewhere skips deferred cleanup and makes code untestable.                    | [Uber Go: Exit in Main](https://github.com/uber-go/guide/blob/master/style.md#exit-in-main)                                                       |
| GO-014  | major    | Start enums at one, or make the zero value mean "unset", so the zero value is never a valid choice by accident.         | An uninitialised field shouldn't quietly mean the first option.                        | [Uber Go: Start Enums at One](https://github.com/uber-go/guide/blob/master/style.md#start-enums-at-one)                                           |
| GO-015  | major    | Use `defer` to release locks, files and other resources.                                                                | A later early return can't skip the release.                                           | [Uber Go: Defer to Clean Up](https://github.com/uber-go/guide/blob/master/style.md#defer-to-clean-up)                                             |
| GO-016  | minor    | Reduce nesting: handle errors and special cases first and return early.                                                 | The main path stays at the left margin.                                                | [Uber Go: Reduce Nesting](https://github.com/uber-go/guide/blob/master/style.md#reduce-nesting)                                                   |
| GO-017  | minor    | Don't name things after built-ins such as `error`, `string`, `len` or `copy`.                                           | Shadowing a built-in confuses readers, and breaks later code in the scope.             | [Uber Go: Avoid Using Built-In Names](https://github.com/uber-go/guide/blob/master/style.md#avoid-using-built-in-names)                           |
| GO-018  | minor    | Use field names when you initialise structs.                                                                            | `User{Name: n, Admin: false}` survives a reordered struct; `User{n, false}` doesn't.   | [Uber Go: Use Field Names to Initialize Structs](https://github.com/uber-go/guide/blob/master/style.md#use-field-names-to-initialize-structs)     |
| GO-019  | minor    | Write repeated test cases as a table, and keep branching logic out of the table.                                        | Each case is one line, and a new case is one more.                                     | [Uber Go: Test Tables](https://github.com/uber-go/guide/blob/master/style.md#test-tables)                                                         |
